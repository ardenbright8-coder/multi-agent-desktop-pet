# 派活单

**一句话**：写死了的重复活拆成单子交出去，我只读报告、跑验收、抽查。单子比活短、验收判得出对错，才值得派。

命令格式在仓库根 `AGENT_INTEGRATION.md` 的「看板派活单」节。

## 一、先判这摊活派不派

三条全占才派：

1. **单子比活短得多**：要求写死、照现成套路干，几行字交代得清
2. **验收判得出对错**：有命令跑出红绿，或抽查几处就知道整批行不行
3. **能按文件分开**：每张单子的「只许动」互不重叠

占不全就自己干：还在探路、要边做边看用户反应的；我自己 10 分钟内干得完的（写单子加审核的开销是固定的，小活反而亏）；几张都得改同一份文件的——合成一张，或者排成前后两批。

- ❌ 面板小样第一版：要用户看了才知道要不要，单子写不清，派出去回来多半重做
- ✅ 给 40 个夹补门牌：规矩现成，一个夹一个样，体检脚本一跑就知道整批过没过

**算做完**：说得出这摊活三条各怎么占的；占不全就自己干，跟用户说一句为什么不派。

## 二、写单子

- 一张一件能独立干完的事，一批最多 3 张，多了下一批
- 默认进 Pi 组（他的 Command Code、OpenCode Go 套餐用不完）；派 Claude 组要他点名
- 一个窗口干一张到底；要三个人干就写三张，他开三个窗口。领单子的窗口自己不再派人

每张的 `detail` 照这六栏写：

```
目标：一句话，干完是什么样
只许动：文件a；文件b（不改文件写「无」）
做法：照哪个现成套路、哪份说明（路径写全）
验收：判得出「做到了 / 没做到」的标准——命令加期望结果，或者抽查哪几处
自测：跑什么命令
做不到：卡两次就停，写进报告交回来
```

- ❌ 验收：门牌写清楚
- ✅ 验收：每个夹都有 `00_这夹干嘛的.md`，开头有「这是啥」「谁看」两栏；`python scripts/库体检.py --夹 <路径>` 0 报错

**算做完**：每张六栏都填了，验收那栏拿给不知道这事的人也判得出对错；几张的「只许动」两两不重叠。

## 三、写进看板，交给用户

单子存成 JSON，敲 `paihuo --file`。跟用户说：写了几张、在哪个组、点其中任一张左边六个点「一键启动」，每个窗口看一眼再按回车。

**算做完**：命令回「派活单已写进看板：N 张同一批」，用户知道去点哪。

## 四、审交回来的

报告挂在条目下面，条目标「干完待审」。`show <组名> <号码>` 只读那一张，或者读它的单独文件。

审三步，前一步不过就不往下：

1. **看证据**：报告里改了哪些文件、跑了什么、结果什么样
2. **对范围**：`git diff --stat`（或看文件改动时间）对照「只许动」——动了单子外的文件就是跑偏
3. **跑验收**：我自己跑一遍单子里的验收命令，再抽查几处；抽查出问题才往深读代码

小毛病我顺手修；跑偏严重的重写单子再派，不在原窗口来回拉扯。审完交用户实测，他说行，条目下点「可以，删掉」（或我带他原话 `remove`），单独文件跟着删。

**算做完**：每张都做到：报告读了、范围对过、验收命令我亲手跑过、结果交给用户了。
