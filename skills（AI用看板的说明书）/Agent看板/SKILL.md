# Agent 看板

看板命令（下面简写成 `看板`）：
```
node "F:\程序\0016_多Agent桌面宠物\scripts\bookmark-cli.mjs"
```

号码全板统一（各组 → 交接单专区 → 待定一路往下编），一个号只有一条。

## 接活：他叫你接第 N 条，或把某条的单独文件拖进来、贴进来

`看板 next N --by <窗口名>`（拖进来的用文件名里的 id）——一步完成「读这条 + 标在干」，吐回来的是这条原文和干活规矩，照着干，不用先 show、不用读别的。

- 他说只看、看看这条，才不接
- 窗口名取「家名-活的俗名」（如 `Claude-强带弱方案`），别跟开着的窗口重名
- 原文对不上他说的事（号码跟着拖动会变）→ 照吐回来的 release 命令放回，再问他
- 报「X 在干」领不到 → 问他那个窗口关没关；关了就 `看板 release <id> --by X` 再 next。领着的窗口一小时没动静的，next 时程序自己接过来，不用问
- 他说这张先不做、以后再说 → `看板 挂起 <号> --why "他原话"`（收到专区最底下）；他说要做了，直接 next 它就自动取消挂起
- 吐回来带【先整理清单】或【打勾清单】→ 照它干：整理清单、打勾都由你这个干活的 AI 亲手做，不交给便宜模型、不交给子 agent（他：小模型理解力不行，容易跑偏）

## 接项目页的活：他拖来、贴来「看板项目「X」的…」，或只说项目名＋第几步

- 贴来那几行带着完整路径和项目夹：直接读那份；它开头点名要读的同夹文件，照「项目夹」那行的路径读
- 只说了项目名（「库管第 2 步派活」）：项目夹都在 `F:\应用数据\AgentPetHub\bookmark\projects\<项目名>\`，名字说歪了就列这一层对一下（这里不在 E 盘搜索范围，别去搜）
- 一份派活稿里有好几张（2-A、2-B…）：只干他点名那张，读完那一节就开干

## 只看不接

- 他点了号码 → `看板 show 7`（`7-9`、`7,9,12`、`捆2` 也行），不先 list
- 他说了件事、没点号码（「看板里语音那条」）→ 有 `kb-search-board` 工具就先搜一句（意思对上就行，说歪的名字也认得），只读搜到的那份单独文件；没这个工具照下一条
- 没点号码、问有啥活 → `看板 list --to <组名>`（交接单专区 `list --handoff`）只看标题，挑出相关的再 show
- 图跟这次的活有关才打开；只看不接的不标在干；`remove` 只在他点名删时用；`list --json` 是整组原文，只给程序用

## 别的活按需读一份（都在本夹）

| 碰到什么 | 读哪份 |
|---|---|
| 他说写交接单、窗口快满要交出去；接一张交接单（他说「开个新窗口」不走这份，直接开窗口带上任务） | `交接单.md` |
| 把写死的活拆给便宜 AI、一键启动、他说「直接开」、审交回来的报告 | `派活单.md` |
| 分捆、工兵按捆一条条领、调度收件箱 | `看板派工.md` |
| 命令全表、记一条（`add`）、派给别家 | 仓库根 `AGENT_INTEGRATION.md`；`看板 --help` |

命令报「看板没开」→ 自己把桌宠开起来，等十秒重试，不用问他（开法在 `交接单.md` 一、⑤）。

**算做完**：读进来的只有点名那几条（或那个文件、或一份标题清单）；接了的条目显示「在干」。
