# 询问与权限面板 · 表述规则

## 一句话原则

宠物不是照抄 Agent 的长篇分析，也不是只给半截结论。它要把当前事情压成一段完整、口语化、能直接作决定的说明。

## 每次怎么总结

按下面顺序组织，但不要把这些词当成栏目逐条念出来：

1. **现在在做什么**：标题一句话说清当前任务。
2. **现在是什么情况**：缺了什么、哪里不合适、什么原因把事情带到这一步。
3. **为什么要处理**：说真正原因，不能写“因为需要你回答才能继续”这种废话。
4. **建议怎么做**：说推荐办法，以及为什么推荐。
5. **会动到哪里**：说会新增、修改或删除什么，有没有负面影响，能不能回退；没核实就直说“还没核实”。
6. **让用户选择**：接上 Agent 原来的选项，并保留自己输入。

## 说话要求

- 用同事之间说话的口气，先说事实，再说建议。
- 一般写成一个短段落，三到五句话；事情复杂时可以稍长，但不能把 Agent 的完整思考过程搬过来。
- 不说“路由、绑定、索引、影响目标、设计材料”这类用户不需要理解的黑话。必须用时，顺手翻成人话。
- 不重复问题，不用“需要补充信息后才能继续”冒充原因。
- “为什么”必须讲前因；“影响”必须讲具体会动到什么，以及有没有坏处。
- 不确定的内容标明“还没核实”，不能猜成事实。

## 内容必须是活的

面板文字不能写死。每次都根据当前 Agent 事件重新总结：

- **文件和文件夹**：说现在缺什么、准备在哪新增或修改、会不会覆盖现有内容。
- **class 或代码**：说当前哪段功能不满足需要、准备改哪个模块、可能影响哪些调用。
- **配置**：说当前设置造成什么结果、准备改哪项、是否需要重启、怎么回退。
- **代理或网络**：说现在流量怎么走、准备换哪条规则或出口、可能影响哪些设备或连接。
- **命令和工具**：说命令要完成什么、会读写哪里、是否有删除、提权或不可逆操作。
- **权限请求**：说为什么现在需要权限、权限只管这一次还是整次会话、拒绝后会发生什么。

## 选项怎么处理

- 优先保留 Agent 给出的原选项、顺序和推荐项，不擅自改掉它真正支持的能力。
- 普通询问最后加“自己输入”，让用户写自己的做法。
- 权限面板只显示当前 Agent 真实支持的范围，例如“允许一次”“本次会话允许”“拒绝”。不支持的权限范围不能硬造。
- 用户自己输入的限制或新命令，作为这次回答原样回传，不替用户偷偷扩写权限。

## 关闭和回传

- 右上角关闭和底部关闭都只是收起面板，不代表同意。
- 点确认后才回传选中的答案，并自动关闭面板。
- 关闭但没有回答的事件仍留在会话索引里，用户之后还能找回来。
- 回传失败时不能假装成功；面板要说明失败，并给出“回原 Agent 窗口处理”。
