# 看板整理（内置模型用）

**一句话**：看板里内置的便宜模型整理一轮分四步，每步发给它的规矩是这夹里的一份 md；改哪步的毛病就改哪份。

每份开头 `---` 包着的是给维护的 AI 看的说明，程序读的时候去掉；下面的正文原样发给模型。正文里 `{{…}}` 由程序填（捆标题写法、代码卡死的字数和禁用词），别写死数字。

## 一、四步各是哪份

| 步 | 干什么 | 文件 | 他在设置窗口能不能改 |
|---|---|---|---|
| ① 读条目 | 一条一问、看图，写项目名、小标题、小结 | `读条目.md` | 只读 |
| ② 分捆 | 拿小卡片把新条目归进捆 | `分捆.md`（夹带 `捆标题写法.md`） | 能改，改过的存看板数据夹 `AI整理规矩.md`，有它就不用这份 |
| ③ 起捆名 | 捆里条目变了，重写大标题 | `起捆名.md`（夹带 `捆标题写法.md`） | 只读 |
| ④ 检查 | 挑放错的挂小橙点，一条不挪 | `检查.md` | 能改，改过的存 `AI检查规矩.md` |

程序硬卡的那些（不跨组、不拆用户的捆、捆名最长几个字、禁用词）不在这夹，在 `src/bookmark/organizer.ts` 的 `hardRulesText()` 和过筛函数里，模型说了也执行不了。

## 二、改完怎么生效、怎么验

- [ ] ① 改哪份就只改哪份；两步共用的捆标题写法只改 `捆标题写法.md`
- [ ] ② 正文要回 JSON 的地方，示例和要求里引用别的话一律写「」：弱模型照抄英文双引号会把自己的 JSON 弄坏（2026-10-13 两次「没读成」就是这个）
- [ ] ③ 跑 `npm test`，`bookmark-organizer.test.ts` 里「内置模型的规矩从 skills 夹读进来」那条查：文件都读得到、`{{}}` 全填上、开头说明去掉了
- [ ] ④ 重开桌宠才读新规矩（开发时读仓库这份，打包后读 `npm run build` 拷进 dist 的那份）。`读条目.md` 一改，看板上每条都会按新规矩重读一遍，正常

**算做完**：测试全过；看板设置窗口「规矩」页里那一份显示的就是改后的正文。
